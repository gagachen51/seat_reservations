# 系统说明

> 项目：智慧自习室预约管理系统（`seat_reservation/`，v2.0.0）
> 需求基线：《需求规格说明书》v1.2（2026-10-15）
> 代码基线：9,300 行 Python，62 个 HTTP 接口，17 张业务表（另有 1 张迁移记录表），测试 115 通过 / 1 跳过
> 本说明只写**实际已实现**的部分，不把需求书里的目标功能等同于已完成功能。
> 基线数字复核时间：2026-10-31（跳过数为**未安装 playwright** 时的口径；装上后为 115 通过 / 3 跳过）。

## 1. 项目概述

系统实现「预约 → 签到 → 使用（暂离 / 返座）→ 签退或超时释放」的完整闭环，并在其之上提供座位封禁、强制释放、候补补位、违规申诉、信用分限制、投诉反馈、座位评价、运营看板与参数配置。

交付三种形态，共用同一套业务代码：

| 形态 | 入口 | 适用场景 |
|---|---|---|
| 桌面窗口 | `desktop_launcher.py` → `dist/自习室预约/自习室预约.exe` | 单机使用，双击即开，无浏览器地址栏 |
| 网页版 | `python run.py serve --port 8010` | 浏览器访问，便于多人同时查看 |
| 安装包 | `dist/setup.exe` | 分发给他人，自动安装、建快捷方式、可卸载 |

领域规则（BR / PR / ST）**只在 `domain/` 实现一次**，`service/` 只负责事务边界，`storage/` 只负责表映射，`api/` 只做 HTTP 协议转换，`web/` 只负责展示。改一条规则不需要同时改五个地方。

## 2. 技术选型与架构

### 2.1 选型结论

| 决策 | 选择 | 理由 |
|---|---|---|
| 后端框架 | **FastAPI 0.115.6** | 自动生成 OpenAPI 文档，Pydantic 做入参校验，路由层只做协议转换 |
| 存储 | **SQLite（标准库 `sqlite3`）** | 无需部署数据库，单文件持久化，事务与关系查询齐全；重启后数据仍在 |
| 前端 | **原生 HTML / CSS / JavaScript** | 不引入构建链与前端框架，图表用原生 SVG 手写；单文件即可部署，无 CDN 依赖 |
| 桌面外壳 | **pywebview 6.2.1（edgechromium 后端）** | 直接驱动系统 WebView2，无需自带 Chromium；支持无边框窗口 |
| 打包 | **PyInstaller 6.22.3** | 生成单文件 exe，目标机无需 Python |
| 时间 | **显式注入 `now`** | 领域方法不读系统时钟，测试与演示可固定时间，保证结果可复现 |

### 2.2 为什么不用 Electron / Tauri

Electron 需自带一整个 Chromium（100MB+），Tauri 需 Rust 工具链。本项目页面是纯静态资源，WebView2 已能满足，引入额外技术栈的收益不足以抵消体积与构建复杂度。

## 3. 核心业务与状态机

### 3.1 主流程

```text
选座 → 创建预约（占用时段）→ 签到（窗口内）
     → 使用中 ⇄ 暂离（限时保留）→ 签退（完成）
                    ↓
              超时未签 / 暂离超时 → 判违约 → 扣信用分 → 释放座位 → 候补顺延
```

### 3.2 SM-01 预约记录状态（7 个）

| 状态 | 中文 | 说明 |
|---|---|---|
| `pending` | 待签到 | 已占用时段，等待签到 |
| `in_use` | 使用中 | 已签到，正常使用 |
| `away` | 暂离 | 临时离开，座位保留限时 |
| `completed` | 已完成 | 正常签退 |
| `cancelled` | 已取消 | 用户主动取消 |
| `no_show` | 已违约 | 超时未签到 |
| `released` | 已释放 | 被管理员强制释放或座位封禁连带释放 |

终态：`completed` / `cancelled` / `no_show` / `released`。终态不可再变更，可被 `prune` 子命令清理。

### 3.3 SM-02 座位状态（6 个，派生）

座位状态**不单独存储**，由「当前时刻 + 该座位的预约记录 + 封禁记录」实时推导：

| 状态 | 中文 | 推导条件 |
|---|---|---|
| `available` | 空闲 | 当前时段无有效预约 |
| `reserved` | 已预约 | 有 `pending` 记录 |
| `occupied` | 使用中 | 有 `in_use` 记录 |
| `held` | 暂离保留 | 有 `away` 记录 |
| `maintenance` | 维护中 | 座位被标记维护 |
| `disabled` | 停用 | 座位被停用或封禁 |

这样设计的好处：预约状态一变，座位状态自动跟着变，不会出现两处状态不一致。

### 3.4 并发与幂等

- 创建预约在一个事务内完成「检查冲突 → 写记录 → 占用时段」，靠唯一索引兜底，并发下不会超卖；
- 超时扫描（`sweep`）可重复执行，同一预约不会被重复判违约；
- 接口写操作要求 CSRF 令牌，重复提交不会产生重复业务。

### 4.1 业务规则 BR

| 编号 | 内容 | 实现位置 |

| BR-15 | 连续 3 次未签到触发 7 天禁止预约，与信用分限制独立判定 | `domain/engine.py` |

| BR-18 | 现场巡检手动违约须填核实说明；可选仅警告或强制释放；扣 5 分并记审计 | `domain/engine.py` |
| BR-19 | 投诉与反馈闭环：提交 → 管理员填反馈办结 → 学生可评价；办结可联动手动违约 | `domain/engine.py` |
| BR-20 | 30 天窗口内有效违约 ≥ 3 次自动拉黑 7 天；管理员可人工拉黑/解除；与信用分、连续违约限制并列 | `domain/engine.py` |
| BR-21 | 仅本人已完成预约可评价一次，1~5 星；管理员可回复；≤ 2 星可联动维护停用并取消受影响预约 | `domain/engine.py` |

| `test_jobs.py` | 调度器、超时扫描、候补顺延 |
| `test_concurrency.py` | 并发预约不超卖 |
| `test_e2e.py` | 真实浏览器端到端（默认跳过） |

### 6.2 已实测的验收点

- 同座位同时段第二条预约被拒（BR-11），不产生第二条有效记录；
- 签到窗口内外行为差异，超时判违约并扣分；
- 暂离超时自动释放，座位回到空闲；
- 候补队列在座位释放后自动顺延；
- 四种角色越权访问返回 403；
- 服务重启后数据仍在（SQLite 持久化）；
- 并发发起同座位预约，只有一条成功。

## 7. 桌面版与安装分发

### 7.1 桌面窗口

`desktop_launcher.py` 做四件事：启动本地服务 → 等待健康检查通过 → 创建无边框窗口 → 关闭窗口时停止服务。

窗口顶部是 44px 自绘标题栏：左侧蓝色座椅图标与标题，右侧最小化 / 最大化 / 关闭，整条可拖动、双击最大化。没有系统标题栏，与页面连成一体。

> 实现细节：pywebview 的 winforms 后端在无边框模式下会因无障碍属性递归而卡死，因此改用 `edgechromium` 后端直接驱动 WebView2。

### 7.2 安装包

`dist/setup.exe`（32MB 单文件）行为：

1. 安装位置**可自选**，默认 `%LOCALAPPDATA%\Programs\SeatReservation`；
2. 复制 171 个程序文件（`_internal` 170 + 主程序 1，随依赖版本浮动），**不包含任何数据库**（避免把开发机的测试数据带给用户）；
3. 创建开始菜单与桌面快捷方式；
4. 写入「应用和功能」卸载项，可正常卸载；
5. 安装前清理历史临时解压残留，退出后清理本次残留。

### 7.3 数据位置与卸载行为

业务数据（`data/`）与日志（`logs/`）**跟随安装目录**：装到 D 盘，数据就在 D 盘，不写 C 盘用户目录。

卸载时只删程序文件、快捷方式与注册表项，**保留 `data/` 中的预约记录**。需要彻底清理时手动删除该文件夹。

### 7.4 首次启动

首次运行自动建库、执行迁移；库为空时写入**演示数据**（四种角色各若干账号、3 间自习室、24 个座位、
21 条预约），并在程序目录生成「初始账号与密码.txt」，初始密码统一 `Seat-Demo-2026`。

**演示模式不强制改密**，登录后可在右上角「修改密码」自行修改。

命令行部署路径额外提供「生成随机初始密码 + 首次登录改密」能力（不属于 v1.2 的强制条款）：
`seat-reservation user create`（或 `user passwd`）不指定 `--password` 时由系统生成随机密码并打印，
该账号带 `must_change_password` 标记，登录后前端会弹出改密提示、改完需重新登录。

### 8.2 外部系统

- 未接入真实统一身份认证（CAS）、门禁（ACS）与消息推送（NOTIFY）；
- 账号为本地密码认证，凭证签发与校验为教学模拟。

### 8.3 并发与数据

- SQLite 单机存储，不支持多节点同时写入；横向扩展需替换为 PostgreSQL 仓储实现；
- 未做容量压测，200 并发指标无实测数据；
- 时间使用本地 naive `datetime`，不含时区换算。

### 8.4 分发

- 仅支持 Windows，跨平台需在对应系统重新打包；
- 安装包未做数字签名，首次运行可能出现「未知发布者」提示（缺证书，非缺陷）；
- 浏览器兼容性仅验证 Chromium 内核。
