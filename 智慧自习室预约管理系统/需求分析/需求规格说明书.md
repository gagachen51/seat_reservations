## 1. 项目概述

### 1.1 问题与背景

自习座位目前"先到先得"，缺乏可核验的占用约定与回收手段：热门区域一早被占满，却存在"占座不来"；管理员只能人工巡查、口头劝离，处置标准不统一；使用数据缺失，无法评估资源是否匹配需求；对反复违规者没有约束手段。

| 编号 | 现状问题 | 影响 |
|---|---|---|
| PB-01 | 自习室"先到先得"，热门区域座位紧张，早上开馆即被占满 | 学生自习需求无法保障，到馆时间浪费 |
| PB-02 | 存在"占座不来"现象（放本书占位一整天） | 座位利用率低，学生满意度低 |
| PB-03 | 人工巡查、口头劝离，管理成本高且缺乏依据 | 管理员工作负担重，处置标准不统一 |
| PB-04 | 无使用数据，无法评估资源是否匹配需求 | 无法科学调整开放区域与时段 |
| PB-05 | 缺少对反复违规者的约束手段 | 违规成本低，占座反复出现 |

### 1.4 系统范围与非目标

**系统做什么**（本次范围）：

- 面向在校学生的自习座位/讨论间**查询与预约**；
- 预约后的**签到、暂离、签退**与**超时自动释放**；
- **违规与信用分**管理、**候补队列**、**消息通知**；
- 面向自习室管理员的**资源维护、座位释放、违规申诉处理、统计报表**；
- 面向系统管理员的**参数配置、角色权限、审计日志**。

**系统不做什么**（非目标，明确排除以避免范围蔓延）：

- 不做门禁闸机的物理控制与硬件改造，只**读取**闸机/扫码签到结果；
- 不做校园统一身份认证系统的实现，只**对接**其认证接口；
- 不做自习室照明、空调等物联网设备的控制；
- 不做缴费、押金、罚款等资金结算；
- 不做课程表、考试安排的排课系统，仅接收其发布的"特殊开放时段"数据。

**系统内部模块、外部系统与人机边界**：

- **系统内部模块**：预约管理、签到与使用管理、违规与信用管理、候补管理、通知编排、资源管理、统计报表、参数与审计；
- **外部系统**：CAS（认证，IF-01）、ACS（签到事件，IF-02）、NOTIFY（消息通道，IF-03）、校历/考试安排（特殊开放时段，IF-04）；
- **人机边界**：学生使用手机端/浏览器；管理员与系统管理员使用管理端 Web；ACS 通过接口推送签到事件（本原型以模拟接口代替，见《A 报告》A.6）。

系统边界、外部角色与外部系统的交互关系见附件 **G-02 系统上下文图**（`models/export/G-02-context-diagram.svg`；源文件 `models/src/G-02-context-diagram.puml`）。

| 前置条件 | 目标座位存在且处于可用状态；操作者具备 PR-05/PR-06 权限 |

| 替代流程 | 封禁时段内无在途预约 → 仅置为维护中，不产生逐条通知（仍记录操作日志） |
| 异常流程 | 未填写原因或影响时段 → 拒绝封禁并提示；操作者为学生或其他越权角色 → 拒绝（PR-06），**座位与预约状态均不变化，不写审计日志** |
| 成功与失败后的结果 | **成功**：座位=维护中，受影响预约=已取消（结束原因=座位封禁取消），学生信用分与违规记录**不变**；**失败/被拒绝**：状态保持，无数据变化 |
| 关联规则 | BR-09、BR-16；PR-05、PR-06；ST-11 |
| 验收标准 | AC-08（受影响预约自动取消、不记违规、有通知） |
| 预期使用频率或触发规律 | 规律：与设备故障率相关，通常为偶发；**具体频次无真实统计 → 待确认**（责任人 `陈景标`） |
| 关联模型 | SM-01（ST-11）、SM-02（维护中）、G-06/G-07；附件位置见附录 A |
| 已知限制 | 封禁的"影响时段"当前未按区间精确过滤受影响预约（会一并取消在途预约），见 A 报告 A.7 的 V-06（暂缓项） |

#### UC-14 违规申诉处理（关键闭环：违约救济）

| 项 | 内容 |
|---|---|
| 编号与名称 | UC-14 违规申诉处理 |
| 参与者 | 学生（本人，PR-09）；自习室管理员（审核，PR-10） |
| 触发事件 | 学生认为违规判定有误（如系统或网络故障），在违规发生后 3 日内提交申诉；管理员审核 |
| 前置条件 | 存在属于本人的"生效"违规记录；距违规发生不超过 BR-17 规定的申诉窗口 |
| 主流程 | 1) 校验申诉人身份与申诉时限（PR-09、BR-17）；2) 违规记录置为"申诉中"并记录理由与时间；3) 管理员核查依据（系统日志、现场记录等）后作出审核决定；4) 审核成立 → 撤销违规、按分值恢复信用分、必要时解除限制、记录审计日志并通知学生；5) 审核不成立 → 维持违规、通知学生并记录审核说明 |
| 替代流程 | 管理员需要补充证据 → 记录待处理状态（本组口径：保持"申诉中"直至作出决定） |
| 异常流程 | 超过 3 日提交 → 拒绝并说明时限（BR-17）；代他人提交 → 拒绝（PR-09）；非管理员审核 → 拒绝（PR-10）；申诉期间限制状态**暂不解除**（避免借申诉规避限制） |
| 成功与失败后的结果 | **成立**：违规状态=已撤销，信用分恢复对应分值，关联限制按规则重新判定；**不成立**：违规状态=生效（保持），信用分不变 |
| 关联规则 | BR-06、BR-17；PR-08、PR-09、PR-10 |
| 验收标准 | AC-12（3 日内申诉可受理，审核成立后撤销并恢复且留痕） |
| 预期使用频率或触发规律 | 规律：集中在考试周或系统异常之后；**具体申诉率无真实数据 → 待确认**（责任人 `陈景标`） |
| 关联模型 | G-04 活动图管理员分支；违规记录状态（生效 → 申诉中 → 已撤销/生效） |

## 3. 领域与数据

### 3.1 术语表（统一术语）

| 术语/缩略语 | 含义 |
|---|---|
| 自习室 | 提供学习座位的物理房间，如第一教学楼 A101 自习室 |
| 座位 | 自习室内的单个学习位置，座位号全局唯一，如 A101-012 |
| 讨论间 | 可多人共同使用、需整体预约的房间类资源，容量 4–8 人 |
| 时段（TimeSlot） | 可预约的最小时间单位，长度 30 分钟，如 2025-10-20 14:00–14:30 |
| 预约记录 | 一次"某人 + 某座位/讨论间 + 某连续时段"的占用约定，系统的核心业务对象 |
| 签到 | 学生在预约时段开始前后规定窗口内到达并确认开始使用 |
| 暂离 | 使用过程中临时离开，座位在保留期内不被释放 |
| 签退 | 学生主动结束使用，释放座位 |
| 超时释放 | 达到规则时限后由系统自动结束占用并释放座位 |
| 违约/违规 | 未按时签到、暂离超时未返回、到点未签退等违反规则的行为 |
| 信用分 | 用于约束预约行为的量化指标，初始 100 分，见 BR-06 |
| 候补 | 目标时段座位已满时的排队登记，座位释放后按序通知补位 |
| 有效预约 | 处于"待签到/使用中/暂离"状态的预约记录 |
| CAS / ACS | 校园统一身份认证系统 / 门禁闸机与扫码签到系统（外部系统） |
| 管理员 / 系统管理员 | 自习室管理员（资源与违规处理）/ 系统管理员（参数、权限、审计） |

> 术语在全文、图模型与数据字典中使用**同一套名称**（如"预约记录""暂离""超时释放"）。

### 3.2 核心对象与关系

| 核心对象 | 含义（一句话） | 主要关系 |
|---|---|---|
| 用户 User | 使用系统的人（学生/教师/管理员/系统管理员） | 1 个用户可创建多条预约记录、多条信用记录、多条候补记录 |
| 自习室 Room | 提供座位的房间 | 1 间自习室包含 1..* 个座位 |

### 3.4 数据保留与隐私

- 预约与违规数据保留 2 年（NFR-06），到期归档或按 FR-73 配置清理；
- 学生端不得展示他人姓名与学号（PR-01）；
- 统计报表默认仅出汇总数据，个人明细仅对管理人员可见（PR-11、PR-12）；
- 附件与提交材料中已移除密码、令牌及与核验无关的个人敏感信息。

## 5. 行为与状态

### 5.1 核心业务过程

核心过程为"**预约 → 签到 → 使用（含暂离）→ 签退 / 超时释放**"闭环，泳道与异常分支见附件 **G-04 活动图**（`models/export/G-04-activity-diagram.svg`；源文件 `models/src/G-04-activity-diagram.puml`）。过程要点：

1. **查询与预约**：学生查询可用座位（FR-24）→ 系统逐项校验（BR-07 → BR-03 → BR-01 → BR-02 → BR-11）→ 生成"待签到"预约并占用时段 → 发送通知（BR-16）；
2. **签到**：窗口内扫码/闸机签到（BR-04、BR-13）→ 状态转"使用中"；超窗则违约并释放座位；
3. **使用与暂离**：可发起暂离并保留座位 30 分钟（BR-05）→ 返座恢复；超时则释放；
4. **结束**：主动签退（ST-08，正常）或到点未签退由定时任务结束（ST-09，记违约）；
5. **异常与旁路**：座位封禁（ST-11）、管理员强制释放（ST-10）、申诉撤销（BR-17）。

### 5.2 对象生命周期（状态模型）

**SM-01 预约记录状态**（图形见附件 **G-06 状态图**：`models/export/G-06-state-machine-reservation.svg`；源文件 `models/src/G-06-state-machine-reservation.puml`）：

| 状态 | 含义 |
|---|---|
| 待签到 | 预约已创建，尚未签到，等待签到窗口 |
| 使用中 | 已签到，正常使用中 |
| 暂离 | 使用中临时离开，座位在保留期内不被释放 |
| 已完成 | 正常签退或到点结束，占用已释放 |
| 已取消 | 学生自助取消或座位封禁导致系统取消 |
| 已违约 | 超过签到窗口未签到，系统关闭 |
| 已释放 | 因暂离超时或管理员强制释放而结束占用 |

**SM-02 座位状态**（图形见附件 **G-07 状态图**：`models/export/G-07-state-machine-seat.svg`；源文件 `models/src/G-07-state-machine-seat.puml`）：

| 状态 | 含义 | 进入条件 |
|---|---|---|
| 空闲 | 当前时段无有效预约与占用 | 无有效预约 / 占用结束 |
| 已预约 | 存在"待签到"预约，尚未开始使用 | 创建预约成功 |
| 使用中 | 对应预约已签到 | ST-01 |
| 暂离保留 | 对应预约处于暂离 | ST-05 |
| 维护中 | 管理员封禁（BR-09） | UC-12 |
| 停用 | 资源停用（FR-21） | UC-11 |

座位状态由预约记录状态派生：ST-00 → 已预约；ST-01 → 使用中；ST-05 → 暂离保留；ST-07/ST-08/ST-09/ST-10/ST-11 → 空闲；ST-13（创建失败）不改变座位状态。
