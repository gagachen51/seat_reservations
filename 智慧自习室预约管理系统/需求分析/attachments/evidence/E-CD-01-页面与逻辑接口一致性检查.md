# E-CD-01 页面与逻辑接口一致性检查（静态走查证据）

| 项 | 内容 |
|---|---|
| 证据编号 | E-CD-01 |
| 版本 / 日期 | v1.0 / 2026-10-29（复核） |
| 类型 | 页面与业务逻辑接口的一致性检查结果（原文档 B.4 节"E-04 原型演示、测试或运行结果"） |
| 支持的任务、需求或记录 | A.6 原型走查与验证记录 PV-01、PV-08；NFR-05（易用性/操作连贯性） |
| 检查对象 | `prototype/index.html`（页面元素）、`prototype/app.js`（页面脚本）、`prototype/domain.js`（领域接口） |
| 检查方式 | 静态解析：提取 `app.js` 中通过 `$('id')` 引用的全部元素 id，与 `index.html` 中定义的 `id` 集合比对；提取 `app.js` 调用的全部 `core.*` 接口，与 `domain.js` 的导出集合比对 |
| 运行日期 | 2026-10-15 |

## 检查结果

```
app.js 引用的静态 id 数: 40   index.html 定义的 id 数: 44
MISSING_IN_HTML: []
app.js 使用的 core API 数: 23   MISSING_IN_CORE: []
```

## 结论

- `app.js` 引用的 **40** 个页面元素 id 全部在 `index.html` 中存在，无"脚本引用了页面上不存在的控件"（即按钮点了没反应）的缺陷；
- `app.js` 调用的 **23** 个领域接口全部存在于 `domain.js` 的导出中，无"调用了未实现的业务能力"的情况；
- `index.html` 中另有 4 个 id 未在 `app.js` 中静态引用（`seat-*` 座位卡片、`res-*` 预约卡片、`param-val-*` 参数显示、`param-input-*` 参数输入），它们由脚本**动态生成**，属于正常情况；
- 该检查属于静态走查，配合 E-TEST-02 的动态交互走查共同支撑 A.6 节"页面与流程走查：信息是否齐全、操作是否连贯"的结论。

> 复现方式：在 `prototype` 目录用任意脚本解析 `app.js` 与 `index.html` 的 id/接口集合即可，无外部依赖。
