# 原型说明（交互验证原型 v2.0）

> 本原型是《智慧自习室预约管理系统》**需求分析阶段**的验证原型，用于 A 报告 A.6 节"原型走查与验证"。
> 业务规则实现与《需求规格说明书》编号严格对应；界面只负责展示与调用，**全部业务判断都在 `domain.js`**。模拟数据均为虚构（教学模拟）。

## 二、六个部分与对应需求（**单页长文档**：6 个部分依次展开，点顶部 1~6 会**平滑滚动**到对应部分）

| 部分 | 能做什么 | 关联需求与规则 |
|---|---|---|
| 1 · 座位资源与预约 | 按区域、状态与**座位属性**（电源 / 靠窗 / 护眼台灯）筛选空闲座位；选择座位与时段后一键预约；满员可加入候补 | FR-24、FR-31、FR-32、FR-34；BR-01、BR-02、BR-03、BR-07、BR-09、BR-11 |
| 2 · 我的预约与签到 | 签到（窗口内）、取消（提前 / 临近两种判定）、暂离与返座、签退；**异常演练按钮**可直接验证超时违约；已完成预约可提交评价 | FR-33、FR-41~FR-43；BR-04、BR-05、BR-06、BR-10、BR-21；ST-01~ST-09 |
| 3 · 预约与违规查询 | 预约流水表 + 违规记录表（区分「系统自动违约」与「管理员手动登记」），支持状态 / 来源 / 处理状态 / 关键词检索，按角色过滤可见范围 | FR-54、FR-64；PR-01、PR-11 |
| 4 · 现场巡检与手动违约 | 今日巡检概览与实时座位看板；点击在用座位可登记违约，**两种处置**：仅警告（状态保持）或强制释放（ST-10）；须填现场核实说明，写审计日志 | FR-65、FR-45；BR-09、BR-18；PR-06、PR-07、PR-17；ST-10、ST-12 |
| 5 · 评价 · 投诉 · 黑名单 | 学生投诉 → 管理员填写**反馈信息**（学生端可见）并可联动违约；信用档案与黑名单（30 天 3 次自动 + 人工拉黑 / 解封）；评价与管理员回复，差评可联动维护停用 | FR-66~FR-68；BR-19~BR-21；PR-18 |
| 6 · 运营数据看板 | 6 项 KPI + 2 张柱状图 + 2 张折线图（各区域座位状态与预约人次、违规类型分布、分时段在馆人数与热度、近 7 日签到率与违约率）；**10 秒自动刷新**，支持区域筛选与网络异常容错 | FR-61、FR-69；NFR-10 |

> 图表为**纯 SVG 手写实现**（不依赖 Chart.js 等外部库），保证离线可用；所有指标由 `domain.js` 从真实记录聚合，不做硬编码。

## 四、人工页面走查建议步骤（8 步，对应 A.5 / A.6 场景）

1. **座位筛选**：初始页勾选「⚡ 带电源」→ 观察网格与"符合条件 N 个座位"同步变化。日期控件已限制在**模拟时钟的可预约窗口**（模拟今天 ~ 今天+7 天，BR-03）内，页面也会明示该窗口，不会出现"选了真实世界的明天却被拒绝"的困惑。
2. **预约主流程**：选 A101-004 → 点「确认预约」→ 切到「2 · 我的预约」看到"待签到"记录。
3. **签到闭环**：连点「+30 分钟」至 14:00 → 签到 → 暂时离开 → 返座确认 → 签退；观察状态与规则编号（ST-01/05/06/08）。
4. **异常演练**：对一条待签到预约点「模拟超时未签到 (ST-02)」→ 观察变为"已违约"并扣分。
5. **现场巡检**：切「管理员 · 王老师」→ 进「4 · 现场巡检」→ 对在用座位点「违约并释放座位」（填写核实说明）→ 回到学生视角确认座位已空闲。
6. **投诉闭环**：学生视角在「5 · 评价·投诉·黑名单」提交投诉 → 切管理员 → 「填写反馈并办结」（可勾选联动违约）→ 学生端可见反馈。
7. **信用与评价**：管理员解封赵敏（黑名单）/ 拉黑王芳；在评价区「回复评价」并联动维护停用。
8. **看板与容错**：进「6 · 运营数据看板」→ 切换区域筛选 → 点「立即刷新」→ 打开「模拟网络异常」再刷新，观察容错横幅与"有效快照"保留。
