## 1. 系统总体架构

```text
浏览器 / pywebview 桌面壳
   │  HTML + app.js（单页，hash 路由，fetch + CSRF 双提交，无构建步骤）
   ▼
api/（app.py 中间件、deps.py 依赖、routes/ 路由）
   │  get_actor / read_engine / write_engine / render / render_page
   ▼
domain/（DomainEngine：全部业务用例与规则判定；resource_rules.py / rules.py 纯函数）
   │  只依赖 ports.Repository 协议（依赖倒置）
   ▼
storage/（SqliteRepository + migrations + seed）
   │  BEGIN IMMEDIATE 写事务 / BEGIN 读事务；SQLite WAL + busy_timeout
   ▼
SQLite（17 张业务表 + schema_migrations，当前版本 v4）
```

v1.2 没有改变分层，只新增一条纵向切片：

```text
resource_rules.py（纯规则，无 I/O）
      ▲
engine.py 资源区（block_seat / unblock_seat / release_seat_block / bulk_create_seats / room_impact / run_timeout_sweep）
      │  ports.Repository 协议
      ▼
repository.py 座位封禁区（_seat / save_seat / get_seat_block / list_seat_blocks / expire_seat_blocks / release_seat_block）
      │
      ▼
seats.maintenance_by_block（v2）+ seat_blocks
      ▲
resource_routes.py（4 个管理端路由）  ←  app.py 注册
      ▲
web/app.js 资源页 / 现场页（封禁记录、批量建座、影响预览）
```

## 4. 模块依赖与数据表所有权

### 4.1 依赖方向

```text
A 账号 ──(角色/状态/会话)──┐
                          ▼
B 资源（rooms/seats/seat_blocks）◄──(座位可用性)── C 预约（reservations/slots/waitlist）
                          │                              │
                          └──────(房间/座位只读)──────────►D 分析（只读）
```

| 依赖 | 本模块如何满足 | 是否阻塞 |

| C 续约要判断座位维护/封禁 | 复用既有 `seat_views` 时间窗派生 + `seat_block_overlaps`；`maintenance_by_block` 不参与可用性判断 | 否 |
| A 停用账号不影响座位 | 不涉及 | 否 |
| D 统计读取房间/座位 | 只新增一列，默认为 0，`SELECT *` 无需改 | 否 |
| B 依赖 C 的预约只读表 | 使用既有 `list_active_overlapping`、`list_reservations`（`Page.total` 取精确计数） | 否 |

## 5. 数据库架构

### 5.1 17 张业务表

`users`、`rooms`、`seats`、`reservations`、`reservation_slots`、`violations`、`credit_logs`、`waitlist`、`notifications`、`audit_logs`、`system_params`、`complaints`、`reviews`、`blacklist`、`seat_blocks`、`sequences`、`sessions`（另有框架表 `schema_migrations`）。

### 5.2 v1.2 变更

```sql
ALTER TABLE seats ADD COLUMN maintenance_by_block INTEGER NOT NULL DEFAULT 0;
```

| 值 | 含义 | 谁能写 |
|---|---|---|
| `1` | 维护状态由封禁流程设置，封禁到期/释放时可自动恢复 | `block_seat`（在非手工维护、非停用前提下） |
| `0` | 手工维护 / 停用 / 正常；封禁到期**不得**自动恢复 | 默认值、`update_seat`（管理员显式设状态）、封禁关闭后的归零 |

### 5.3 关键约束（未变，v1.2 继续依赖）

| 约束 | 作用 |
|---|---|
| `reservation_slots` 主键 `(seat_id, date, slot)` | 座位时段唯一，防超卖 |
| 唯一索引 `ux_slots_user (user_id, date, slot)` | 同一用户同段唯一 |
| `seats.room_id` 外键 `ON DELETE RESTRICT` | 不物理删除自习室，也不允许删有座的房间 |
| `trg_audit_no_update` / `trg_audit_no_delete` | 审计只追加 |
| `ix_seat_blocks_seat (seat_id, start_at, end_at)` | 封禁时间窗查询 |
| `ix_seats_room (room_id)` | 座位按房间筛选 |

### 5.4 迁移执行

`storage/database.py::Database.migrate()` 在一个 `BEGIN IMMEDIATE` 事务内按版本顺序执行未应用的迁移并写 `schema_migrations`；重复调用返回 `[]`（`test_v2_migration_is_idempotent_and_keeps_existing_rows` 断言）。内部健康检查的 `db.schema_version` 现在返回 **4**；公开 `/api/health` 只返回最小状态，不披露数据库细节。

## 6. 核心业务调用流程

### 6.1 创建预约（C，未改）

`POST /api/reservations` → `student_routes.create_reservation` → `engine.create_reservation` → 校验窗口/时长/额度/座位状态/**封禁时间窗** → `repository.insert_reservation` + `occupy`（写 `reservation_slots`，唯一约束兜底）。

B 侧的接口点：`engine.create_reservation` 里的 `seat.admin_status == 'maintenance' or repo.seat_block_overlaps(...)` —— 未来封禁靠时间窗拦截，**不依赖 `admin_status`**，所以 v2 里“未来封禁不改状态”是安全的。

### 6.2 封禁座位（B，v1.2 重写）

```text
POST /api/admin/seat-blocks
  → admin_routes.block_seat（既有路由，未改签名）
  → engine.block_seat
      ① _require(room_admin/sys_admin, PR-06)；原因≥2 字；窗口合法
      ② repo.insert_seat_block（先落记录）
      ③ resource_rules.seat_state_after_block → (admin_status, maintenance_by_block)
      ④ repo.save_seat
      ⑤ repo.list_active_overlapping → 逐条 _release_reservation(..., CANCELLED, seat_blocked)
         （BR-09：取消受影响预约、不记违规、发站内通知）
      ⑥ _audit("seat_block", before/after 含封禁窗口与标记)
```

### 6.3 封禁到期 / 解封（B，v1.2 新增）

```text
定时扫描：service/scheduler.run_once → engine.run_timeout_sweep
  → repo.expire_seat_blocks(now)：关闭 end_at <= now 且未释放的记录
  → 每座位：repo.active_seat_blocks → resource_rules.seat_state_after_blocks_closed
      标记=1 且 maintenance → available；disabled/手工维护/available → 状态不变、标记归零
  → 有变化才 save_seat + _audit("seat_block_expired")
  → summary["seat_blocks_expired"] = 关闭条数

按记录解封：POST /api/admin/seat-blocks/{block_id}/release
  → engine.release_seat_block
      · 记录不存在 404；已释放 400 ST-12；原因<2 字 422
      · 停用座位 + restore_seat=true → 400 PR-06（拒绝且无副作用）
      · repo.release_seat_block（只关一条）
      · restore_seat=true 且 can_restore_seat → available + 标记归零
      · 默认只把标记归零，不改 admin_status
      · _audit("seat_block_release")

整体解封（既有）：DELETE /api/admin/seat-blocks/{seat_id}
  → engine.unblock_seat：关闭该座位全部未释放记录 → 按规则恢复（仅封禁管理的维护）
```

### 6.4 批量建座（B，v1.2 新增）

```text
POST /api/admin/seats/bulk
  → engine.bulk_create_seats
      · _require(PR-05)；1 ≤ 条数 ≤ 100；房间存在；编号非空且批内不重复；不与既有座位冲突
      · 逐条 _validate_seat_shape（讨论间 4~8 人，其他容量必须 1）+ repo.save_seat
      · 任一条失败抛 AppError → 外层写事务回滚（全量原子）
      · _audit("seat_bulk_create")
```

### 6.5 停用影响预览（B，v1.2 新增，只读）

```text
GET /api/admin/rooms/{room_id}/impact?status=closed
  → engine.room_impact
      · 房间存在；status ∈ {open, closed}
      · 按 pending/in_use/away 分别 repo.list_reservations(room_id, status=…) 取 Page.total 精确计数
      · items 取前 20 条预览；不写任何表
```

### 6.6 续约 / 候补取消（C）、运营统计与导出（D）

由 C/D 实现；B 只保证 `seats`/`seat_blocks` 的读取接口（`seat_views`、`seat_block_overlaps`、`list_active_overlapping`）签名不变，避免影响他们。`seat_views` 无需修改：它已按 `released_at IS NULL AND start_at < ? AND end_at > ?` 派生维护态。

## 9. 已知限制

| 限制 | 影响 | 处理 |
|---|---|---|
| `room_impact` 用 `Page.total` 逐状态计数（3 次查询） | 大房间多次查询，但均为 COUNT + LIMIT 20 | 数据量级小，可接受；后续可在 `analytics_queries.py` 用一条聚合 SQL 替代（D 的模块） |

| 封禁与“资源停用保留预约”口径未统一 | 封禁按 BR-09 取消受影响预约 | Q-08 待负责人确认，本期不改 |
