# 局域网多人访问

主机运行一个 FastAPI/Uvicorn 服务，手机和其他电脑用浏览器访问它。所有请求使用主机上的同一个 SQLite 文件，客户端不需要安装 Python 或复制数据库。已有的 WAL、写事务和座位占用约束继续负责并发控制；SQLite 写入仍是串行的。

## 主机启动

在项目的 `seat_reservation` 目录打开 PowerShell：

```powershell
.\.venv\Scripts\python.exe run.py --db var/web.db serve --lan --port 8010 --demo
```

`--demo` 只用于课堂演示，空数据库会生成演示账号。已有业务数据库请沿用其路径，不要换成另一个空库。多人测试只运行一个服务进程，不使用 `--reload`。

等待终端显示 Uvicorn 启动成功。`--lan` 相当于现有的 `--host 0.0.0.0`，与 `--host` 不能同时使用。没有指定时仍只监听本机；`SEAT_HOST` 和 `SEAT_PORT` 环境变量可设置默认值，命令行参数优先。例如 PowerShell 中设置 `$env:SEAT_PORT = "8010"`。启动器不会自动加载 `.env` 文件。

## 其他设备连接

1. 主机和其他设备连接同一 Wi-Fi 或局域网。
2. 在主机运行 `ipconfig`，找正在使用的 Wi-Fi/以太网网卡 IPv4 地址，例如 `192.168.1.20`。启动输出也会列出候选地址，VPN/虚拟网卡地址可能不适用。
3. 在其他设备浏览器打开 `http://192.168.1.20:8010/`，用各自账号登录。不要填写 `localhost`、`127.0.0.1` 或 `0.0.0.0`。
4. 在 Windows 防火墙提示中允许 Python 在可信的专用网络通信；如需手动添加入站规则，只放行实际服务端口 TCP 8010 和本地子网，不要关闭整个防火墙。

主机必须保持开机、联网并运行服务。若连不上，先在主机访问 `http://127.0.0.1:8010/api/health`，再从客户端访问主机 IP 的 `/api/health`。检查端口、防火墙、代理绕过内网设置，以及路由器是否启用了访客网络或客户端隔离。主机重新联网后 IP 可能变化。

局域网 HTTP 测试使用开发环境且 `SEAT_COOKIE_SECURE=false`；仅用于可信测试网络和测试账号。公网 HTTPS 与 ngrok 的代理配置留到下一步单独处理。

## 共享预约验收

两台设备使用不同学生账号登录，选择同一天、同一座位、同一时段同时预约。应只有一人成功，另一人收到冲突提示；刷新座位列表后应看到占用变化。再预约另一个可用座位，应成功。页面不会自动实时推送其他人的变更，需要刷新或重新查询。

自动化测试：`python -m pytest -q tests/test_network.py tests/test_concurrency.py`。测试覆盖独立会话竞争同一座位、唯一入库和监听配置；不能替代两台真实设备对 Wi-Fi、防火墙的验收。

## 复用依据

- 复用本项目已有 Uvicorn `host`/`port` 参数，不新增服务器框架。Uvicorn 文档入口：https://www.uvicorn.org/settings/ （本次联网查阅受 DNS/403 限制，未声称已读取全文）。
- 已查阅 SQLite 官方适用场景：https://www.sqlite.org/whentouse.html 。SQLite 可以作为网站后端数据库；不要让多台机器通过网络共享目录直接读写同一个数据库文件。
- SQLite 并不等同于 MySQL 的网络数据库服务器。当前小范围测试使用单主机应用服务适合；更大写入量或多台应用服务器需另行评估数据库迁移。

本功能基于 `faadc00e8f36c49ef94614fd41f9dfbc199453f4`，目标分支 `feature/lan-network-access`。组员的后续修复仍需按团队流程合入并重新回归。
