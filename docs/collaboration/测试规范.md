# 测试规范（v1.2）

> 牵头：成员 C（测试规范、全组新路由契约冒烟、预约并发用例）；公共夹具唯一修改人：
> 成员 B；CI 由成员 D 负责，C 复核测试命令。本规范只约束“怎么测、怎么记录、怎么
> 评审”，不包含公共夹具实现，也不替代各模块自己的测试文件。

## 1. 测试分层与责任

| 层次 | 内容 | 负责人 | 工具/位置 |
|---|---|---|---|
| 纯规则单测 | 续约边界、封禁生效、账号状态、统计口径 | 各模块成员 | pytest，无数据库；`tests/test_rules.py`、各模块 `*_rules` 用例 |
| 引擎/事务测试 | 状态机、回滚、审计、通知 | 各模块成员 | `tests/helpers.py` 的 `Env` + `AppContext` |
| HTTP 契约测试 | 路由、权限、错误结构、分页 | 各模块成员写自己的用例；C 维护 `test_new_routes_contract.py` | FastAPI `TestClient` |
| 并发测试 | 续约并发（C）、封禁生命周期（B） | C、B 各自负责 | `ThreadPoolExecutor` + 独立 `AppContext` |
| 端到端 | 学生预约流程、管理员看板 | C 维护，默认跳过 | Playwright（可选，未安装时 skip 并注明） |
| 回归 | 全量既有测试 | 全员 | `.venv/bin/python -m pytest -q` |
| CI | 工作流与执行环境 | D | GitHub Actions，Windows + Ubuntu，Python 3.12 |
| 公共夹具 | `tests/helpers.py`、`tests/conftest.py` | B（唯一修改人），C 复核 | pytest fixtures |

模块专用夹具写在该模块自己的测试文件里；只有两个以上模块共用的夹具才由 B 加到
`tests/helpers.py`，C 复核，其他人不直接改公共夹具。

## 2. 强制规则

1. **不写“假通过”**：没有实际执行的测试不能标记通过；跳过项必须写明原因（如未
   安装 Playwright、其他模块路由尚未合并）。
2. **固定时钟**：使用 `tests/helpers.py` 的 `NOW = 2026-05-11 08:00` 与 `D`，不
   依赖真实当前时间；HTTP 路由需要 `datetime.now()` 时，用 `monkeypatch` 固定
   到 `NOW` 附近，不在断言里比较真实时间。
3. **数据库隔离**：每个测试用独立临时 db（`conftest.py` 已按 node name + uuid 生成），
   不共享状态，不删除既有数据库文件。
4. **不用 `sleep` 等异步**：并发用线程 + 事务边界；调度器用 `run_once(now)` 或
   `env.sweep(now=...)` 显式注入时间。
5. **断言业务后果**：不仅断言状态码，还要查数据库（预约状态、slot 行数、信用分、
   审计、通知、候补状态），避免“接口返回成功但数据没变”。
6. **权限矩阵**：每个新接口至少覆盖“正确角色 200/201、错误角色 403、未登录 401”；
   写请求先通过 CSRF 中间件，再验证认证依赖。
7. **错误结构**：断言 `{ok:false,error:{code,message}}`，规则编号与 SRS 对齐
   （如 `BR-11`、`ST-12`、`PR-03`）；不要只断言状态码。
8. **回归优先**：任何 PR 合并前必须跑全量 `pytest -q`；新增测试不得修改既有断言
   来“迁就”实现；现有测试失败先定位回归，不先改测试。
9. **测试命名**：`test_<规则或场景>_<行为>`，如
   `test_br01_extension_cannot_exceed_max_minutes`、`test_pr04_cancel_notified_does_not_promote_next`。
10. **测试数据**：优先用 `Env` 封装；模块专用夹具写在该模块测试文件；公共夹具变更
    走 SFCR，由 B 应用、C 复核；测试不得依赖真实用户数据或外部网络。

## 3. 本模块（C）的测试交付物

| 文件 | 覆盖重点 | 最低用例 |
|---|---|---|
| `tests/test_extension.py` | 使用中/暂离可延长；pending/终态拒绝；非本人/教师拒绝；30 分钟粒度；BR-01 总时长/关闭时段；BR-02 当日额度；BR-09 维护/封禁/停课；BR-11 座位/本人冲突与相邻边界；审计 before/after；版本回滚；双线程并发；HTTP 401/403/404/409/422 | ≥ 20 |
| `tests/test_waitlist_cancel.py` | queued/notified 取消；Q-05 不自动顺延；只改 status；他人/非学生拒绝；confirmed/expired/cancelled 拒绝；信用/违规/通知无副作用；HTTP 契约 | ≥ 12 |
| `tests/test_new_routes_contract.py` | A/B/C/D 15 条计划路由无 5xx、错误结构统一；C 两条路由必须注册；达到 12 条后强制最低覆盖 | 15 条路由，最低 12 条 |

C 额外负责：`test_new_routes_contract.py` 的维护、测试规范符合性复核、公共夹具的
测试语义复核；**不负责** CI 工作流、公共夹具实现和其他模块的业务测试。

## 4. 执行命令与环境

```bash
# 在 智慧自习室预约管理系统/seat_reservation 下
uv venv .venv --python 3.12
uv pip install --python .venv/bin/python -r requirements.txt

.venv/bin/python -m pytest -q                 # 全量回归
.venv/bin/python -m pytest tests/test_extension.py -q
.venv/bin/python -m pytest tests/test_waitlist_cancel.py -q
.venv/bin/python -m pytest tests/test_new_routes_contract.py -q
node --check src/seat_reservation/web/app.js  # 前端语法检查（可选）
```

- 不安装 Playwright；`tests/test_e2e.py` 保持 skip，并在执行记录中注明原因。
- 路由契约测试会临时装配 A 的 `account_routes`（正式注册由 B 的 SFCR 完成）；
  未合并的 B 路由显式 skip，合并后自动生效。
- Windows 路径使用同样命令；CI 由 D 在 `windows-latest` / `ubuntu-latest` 执行。

## 6. PR 测试自查清单

- [ ] 新增/修改的每条规则都有对应用例，且断言了数据库后果。
- [ ] 每个新路由覆盖 200/201、403、401；错误结构含 `code`/`message`，规则编号正确。
- [ ] 固定时钟、独立 db，无 `sleep`、无真实时间断言。
- [ ] 并发/回滚用例证明失败请求不留下半截数据。
- [ ] 全量 `pytest -q` 通过；既有测试断言未为迁就实现而修改。
- [ ] skip 项写明原因；没有“假通过”。
- [ ] 公共夹具未被直接修改；如需变更，已提交 SFCR 并由 B 应用。

## 7. 评审与责任边界

- C 复核：测试规范符合性、`test_new_routes_contract.py`、公共夹具的测试语义；
  不逐行评审所有人的测试。
- B 复核：`tests/helpers.py`、`conftest.py` 的变更；C 的测试文件由 B 复核。
- 评审重点：业务规则是否与 SRS 一致、权限是否越权、事务边界、错误码、测试是否
  真实覆盖；口头通过不算通过，评审意见必须回复或修改。
