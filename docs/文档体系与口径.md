# 文档体系与口径

本仓库的文档跨越需求、开发、整改与交付四个阶段。为避免把不同阶段的数字当成当前事实，本文说明每类文档的定位、阅读顺序与冲突处理规则。

## 1. 先读什么

第一次接触本项目，按以下顺序阅读：

1. 根目录 [`README.md`](../README.md)：项目定位、交付物、启动方式、账号规则、功能与限制。
2. [`CHANGELOG.md`](../CHANGELOG.md)：版本时间线与每个版本的变更。
3. [`智慧自习室预约管理系统/系统说明.md`](../智慧自习室预约管理系统/系统说明.md)：角色、业务闭环、关键规则。
4. [`智慧自习室预约管理系统/环境清单.md`](../智慧自习室预约管理系统/环境清单.md)：运行环境与配置项。
5. [`docs/系统架构设计报告.md`](系统架构设计报告.md)：分层、数据模型、状态机、接口与规则映射。
6. [`智慧自习室预约管理系统/seat_reservation/技术文档.md`](../智慧自习室预约管理系统/seat_reservation/docs/技术文档.md)：部署、备份恢复、安全设计与验收对照。

需求、过程与整改文档用于追溯“为什么这样做”，不作为当前实现的说明书。

## 4. 历史文档的使用规则

- 历史文档中的版本号、测试数量、迁移版本、启动方式与产物描述，均为**该文档写作时**的基线，不代表当前实现。
- 历史文档中的“未完成”“未验证”结论，只对当时范围有效；其中一部分已在后续版本实现，判断当前状态应查 `CHANGELOG.md` 与代码。
- 历史文档中的接口、表结构与密码策略描述，可能与当前 schema v5 不同；以 `技术文档.md` 与 `系统架构设计报告.md` 为准。
- 本仓库保留历史文档原文，是为了保留评审与整改证据，不回填、不改写其中的测试数据与结论。

## 6. 冲突处理原则

当两份文档对同一事实给出不同说法时，按以下优先级取信：

1. 代码与实测输出；
2. `CHANGELOG.md` 与根目录 `README.md`；
3. 当前交付口径文档（系统说明、环境清单、技术文档、架构报告）；
4. 需求基线文档；
5. 开发过程与安全整改记录。

如果发现当前口径文档与代码不一致，应修改文档而不是修改历史记录；如果发现历史记录与当前实现不一致，应在本文第 5 节补充说明，而不是回填历史文档。
