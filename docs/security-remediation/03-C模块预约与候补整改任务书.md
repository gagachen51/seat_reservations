# C 模块预约与候补整改任务书

> 文档阶段：v1.2–v2.0.3 过程记录（2026-11）。文中的版本号、测试数量、交付形态与启动方式均为当时基线；当前实现为 v3.1.0 / schema v5，采用浏览器访问的 Web 交付，口径见根目录 `README.md` 与 `CHANGELOG.md`。


## 1. 模块职责

C 负责预约、签到、签退、暂离/返座、续约、候补及其状态转换：

- 预约创建、取消、状态转换。
- 扫码签到、ACS 凭证签到、签退、暂离/返座。
- 预约续约（延长时段）。
- 候补加入、确认、取消。
- 超时扫描（no_show、away_timeout、late_checkout、waitlist_expired）。
- 预约并发与事务一致性。

## 3. 问题逐项说明

### M-04 资源状态变更后的预约处理（C 预约侧）

#### 现状

- B 的 `update_room`/`update_seat` 不处理已有预约。
- C 的签到会因房间关闭/座位停用拒绝；sweep 会把仍 pending 的预约判 no_show。
- 已复现：关闭房间后预约仍 pending，sweep 后 no_show、信用下降。
- B 是资源变更主责，C 负责预约状态转换和 no_show 判定的一致性。

#### 具体修改要求

1. **直接复用 B 的统一 helper：**
   - B 提供 `release_affected_reservations(room_id, seat_id, reason, actor, now)`。
   - 受影响预约统一 `cancelled`、`end_reason="resource_unavailable"`；C 不重复实现资源停用入口。
   - 不记 `no_show`、不扣信用。
2. 在 C 的预约状态/扫描逻辑中：
   - sweep 不得把因资源状态变更无法签到的预约判为 `no_show`。
   - 对已 `cancelled`/`released` 的预约不再重复处理。
   - 保证预约状态、slot 占用、信用/违规记录一致。
3. 签到核心在房间/座位不可用时拒绝，但拒绝不能导致后续误判；应与 B 的 helper 处理配合，确保预约已被取消。
4. 通知内容明确“因资源不可用取消，不记违约、不扣信用”。
5. 保持普通用户主动 no_show 的判定不变；只对资源变更导致的不可履约豁免。

#### 涉及文件/接口

- `SR/src/seat_reservation/domain/engine.py:1286-1402`（sweep）
- `SR/src/seat_reservation/domain/engine.py:755-858`（签到核心）
- `SR/src/seat_reservation/domain/engine.py:956-978`（取消）
- `SR/src/seat_reservation/api/routes/student_routes.py` 预约/签到接口
- 与 B 协作：`engine.py:2318-2363,2439-2508`
- 测试：`tests/test_safety_fixes.py`、`tests/test_extension.py`、`tests/test_concurrency.py`

#### 修改边界

- B 负责资源状态更新入口；C 负责预约状态/扫描/信用判定。
- C 不直接修改 B 的 `update_room`/`update_seat` 资源逻辑；通过契约和测试协作。
- 不改变普通 no_show 规则（未签到且无资源异常）。

#### 协作要求

- B：主责资源变更，提供 `release_affected_reservations`；C 直接调用，不复制实现。
- 共享层：通知/审计。
- A：账号/学生视图的状态标签兼容。

#### 验收标准

- 房间关闭/座位停用后，已有预约由 `release_affected_reservations` 统一置为 `cancelled`、`end_reason="resource_unavailable"`，不会 no_show。
- 预约状态/信用/违规/通知一致。
- 重复 sweep 不重复处理。
- 原有正常 no_show 测试仍通过。

### M-06 停用账号 ACS 签到与限制账号续约

#### 现状

- `_check_in_core` 加载用户但不检查 `is_active`、黑名单、信用/连续违约限制。
- ACS `check_in_by_credential` 不依赖登录会话，停用账号旧凭证仍可签到。
- `extend_reservation` 不调用 `_booking_limit`，受限制用户仍可续约。
- 已复现：停用账号在凭证 TTL 内 ACS 签到成功，预约进入 in_use。

#### 具体修改要求

1. 在 `_check_in_core` 中统一检查：
   - `user.is_active`；停用账号拒绝。
   - `_booking_limit(user, now)`；黑名单/信用/连续违约限制按现有规则拒绝。
   - 用户存在且状态有效。
2. ACS 和普通签到共用同一账号校验，不得只检查凭证。
3. `extend_reservation` 在状态/时长/座位检查之外，重新检查账号限制；受限制用户不得续约。
4. 明确错误码：403/409 或业务规则编号；不要只返回通用 500。
5. 检查时序：账号停用后旧会话已失效；ACS 凭证即使未过期也不能绕过。
6. 如果产品意图允许已预约用户完成当前使用，必须由负责人明确，并在测试中记录；默认整改为拒绝。

#### 涉及文件/接口

- `SR/src/seat_reservation/domain/engine.py:755-858`
- `SR/src/seat_reservation/domain/engine.py:981-1098`
- `SR/src/seat_reservation/api/routes/student_routes.py:358-369`（ACS 路由）
- `SR/src/seat_reservation/domain/engine.py:361-384`（`_booking_limit`）
- 测试：`tests/test_extension.py`、`tests/test_safety_fixes.py`

#### 修改边界

- C 负责签到/续约/ACS 账号校验。
- 不修改 `_booking_limit` 的信用/黑名单阈值（除非负责人要求）。
- 共享层/A 负责账号状态写入和会话失效；C 负责使用点复核。

#### 验收标准

- 停用账号普通签到/ACS 签到均拒绝。
- 黑名单/信用限制账号不能签到或续约。
- 正常账号签到/续约不受影响。
- 错误码/规则编号明确，测试覆盖。

### M-07 候补加入/确认校验不完整

#### 现状

- `join_waitlist` 只检查可预约窗口、时段、座位存在、座位冲突；不检查房间状态、座位状态、封禁、开放时间。
- `confirm_waitlist` 检查房间/座位/封禁，但不检查房间开放时间；配置变更后可能生成越界预约。
- 失败时可能遗留/过期候补状态，需要明确。

#### 具体修改要求

1. 抽取/复用预约创建的资源校验：
   - `room.status == open`
   - `seat.admin_status == available`
   - 无重叠 seat_block
   - `within_open_hours(start_slot,end_slot,room.open_slot,room.close_slot)`
   - 座位/用户冲突、配额、本人限制。
2. `join_waitlist` 应拒绝明显不可用的目标（关闭房间、停用/维护座位、封禁时段、开放时间外）。
3. `confirm_waitlist` 必须重新读取最新房间/座位状态和开放时间，再创建预约。
4. 确认失败时：
   - 不生成 reservation/slot 行。
   - 候补状态按契约设为 `expired`/`cancelled`，不重复通知/顺延。
   - 事务回滚或提交明确状态，二者必须一致。
5. 对“管理员缩短开放时间后旧候补确认”增加测试。
6. 保持正常候补顺序/确认/取消流程不变。

#### 涉及文件/接口

- `SR/src/seat_reservation/domain/engine.py:1104-1153`
- `SR/src/seat_reservation/domain/engine.py:1156-1280`
- `SR/src/seat_reservation/domain/reservation_rules.py`
- `SR/src/seat_reservation/api/routes/student_routes.py:192-230`
- 测试：`tests/test_waitlist_cancel.py`、`tests/test_extension.py`

#### 修改边界

- C 主责候补规则/状态。
- B 提供资源状态/座位/封禁查询；C 复用，不复制 B 的状态机。
- 不改变正常候补队列排序/通知人数参数。

#### 验收标准

- 关闭房间/停用座位/封禁时段/开放时间外不能成功加入或确认候补。
- 确认失败不产生预约/slot；候补状态明确。
- 正常候补确认仍生成 pending 预约并通知。
- 并发/配置变更测试通过。

### L-07 候补确认与凭证签发事务/并发一致性（C 侧）

#### 现状

- `confirm_waitlist` 先 `insert_reservation` 再 `occupy`；若 `occupy` 抛 `SlotConflict` 且被捕获返回 failure，外层写事务正常提交，理论上可能留下无 slot 的 reservation。
- 当前预检 + `BEGIN IMMEDIATE` 使该路径难以触发，但结构上存在风险。
- `issue_credential` 并发时后写覆盖先写，先返回的凭证可能失效。
- 未覆盖候补确认/凭证并发测试。

#### 具体修改要求

1. `confirm_waitlist` 中 `insert_reservation`/`occupy` 失败必须抛出异常使事务回滚，或显式清理已插入 reservation，确保不留下部分数据。
2. 明确失败时 waitlist 状态（expired/cancelled）与 reservation 回滚的原子性。
3. `issue_credential` 增加并发保护：
   - 版本/条件更新，或同一预约仅允许一个有效凭证。
   - 并发请求要么返回相同凭证，要么后者明确冲突，不得返回已失效凭证。
4. 增加事务/并发测试：
   - monkeypatch/强制 `occupy` 失败，断言无 reservation 行。
   - 两线程同时签发凭证，断言返回凭证至少一个有效，或一个成功一个冲突。
5. 不改变正常凭证 TTL/签到规则。

#### 涉及文件/接口

- `SR/src/seat_reservation/domain/engine.py:1241-1246`
- `SR/src/seat_reservation/domain/engine.py:718-740`
- `SR/src/seat_reservation/storage/repository.py:702-737,793-810`
- 测试：`tests/test_concurrency.py`、`tests/test_waitlist_cancel.py`

#### 修改边界

- C 主责预约事务/凭证；B 协作 schema/唯一约束。
- 不新增预约表字段，除非负责人批准；优先用现有 version/条件更新。
- 不改变签到凭证格式/TTL。

#### 验收标准

- 强制 `occupy` 失败后无孤儿 reservation/slot。
- 并发凭证请求不返回已失效凭证。
- 正常候补确认/凭证签发测试通过。
