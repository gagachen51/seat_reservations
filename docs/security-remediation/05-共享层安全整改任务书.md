### M-01 登录限流绕过、PBKDF2 写锁、限流内存

> **基线状态：** 已在 `2589354` 完成；以下为审计历史与验收依据，后续只做回归验证。

#### 现状（审计时）

- 限流 key 使用原始 `username.lower()`；查询使用 `username.strip()`。
- `"S1"`、`" S1"`、`"S1 "`、`"\tS1"` 等是不同 key，但同一账号。
- PBKDF2 260k 在 `BEGIN IMMEDIATE` 写事务内执行，持有全局写锁。
- `_failures`/`_locked_until` 无全局清理/容量上限。
- 已复现：同 key 5 次失败→正确密码 429；5 个空白变体失败→正确密码 200。

#### 具体修改要求

1. 统一规范化函数：`strip().casefold()`（或项目确认的 Unicode normalization）；限流 key 与用户查询使用同一值。
2. PBKDF2 校验移出写事务：
   - 先只读获取用户/哈希。
   - 在事务外 `verify_password`。
   - 验证成功后再开启写事务创建 session/更新 last_seen。
3. limiter：
   - 增加定期清理过期失败记录。
   - 设置最大 key 数/单 key 记录上限，超限拒绝或淘汰。
   - 评估账号级 + IP 级双限；多实例部署要求外部限流（Redis）需文档说明。
4. 限流响应保持 429 和现有提示；不要泄露账号是否存在。
5. 测试：空白/大小写/Unicode 归一化、同 key 锁定、变体不绕过、PBKDF2 不持锁、limiter 清理。

#### 涉及文件/接口

- `SR/src/seat_reservation/service/auth.py:37-43,59-162,172-240`（规范化 / limiter / 事务外校验）
- `SR/src/seat_reservation/api/schemas.py:13-15`
- 测试：`tests/test_security_p0_m01.py`（基线已存在）
- `SR/src/seat_reservation/storage/database.py:48-62`
- `SR/src/seat_reservation/security.py:25-35`
- 测试：新增 `tests/test_auth_security.py` 或现有 test_api

#### 修改边界

- 共享层修改 auth/limiter/deps；A 提供 must_change 相关测试。
- 不改变密码哈希算法/迭代次数（除非单独安全决策）。
- 不引入外部依赖；多实例限流作为文档限制。

#### 验收标准

- 用户名空白/大小写变体共用同一限流 key。
- 达标后正确密码仍 429；换变体不能绕过。

### L-05 CSRF 与公共安全中间件

#### 现状

- CSRF 只比较 cookie/header，不与 session 绑定。
- `/api/auth/login` 豁免；`/api/acs/` 整个前缀豁免。
- CSRF 403 在安全头/访问日志设置前返回。
- 无 CORS；安全头基本齐全；生产 cookie Secure。

#### 具体修改要求

1. CSRF token 绑定 session：
   - 登录时生成 token 并存入 session；请求校验 header 与 session token（同时可保留 double-submit）。
   - 会话刷新/登录轮换 token。
2. 登录豁免保持最小；ACS 只豁免实际 ACS 路径，验证 token。
3. CSRF 失败响应也设置安全头并写访问日志/安全日志。
4. 统一安全响应头：CSP、X-Frame-Options、nosniff、Referrer-Policy、Permissions-Policy、Cache-Control。
5. 评估 HSTS（部署层/HTTPS）；不引入 CORS 除非有明确跨域需求。
6. 测试：缺失/错误/过期 token、登录/ACS 例外、403 安全头、session 绑定。
