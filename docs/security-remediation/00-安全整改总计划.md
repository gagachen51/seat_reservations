## 4. 严重程度与整改优先级

### 4.1 严重程度

- **Critical：** 系统全面失陷、任意管理员权限、重大数据泄露、任意代码执行。
- **High：** 实质性权限绕过、访问大量敏感数据、修改重要数据、严重服务影响，或关键安全控制不可用。
- **Medium：** 明确安全风险，但利用条件或影响范围有限。
- **Low：** 配置、信息暴露、边界问题或低影响业务缺陷。
- **Info：** 改进建议、未确认风险或最佳实践。

### 4.2 整改优先级

- **P0：** 阻断发布，必须最先完成。
- **P1：** 优先修复，影响安全控制或业务公平性。
- **P2：** 近期修复，包含权限范围、导出安全、日志和展示问题。
- **P3：** 持续改善，包含边界、并发、约束和低影响问题。

## 5. 分支与集成流程

沿用现有 v1.2 协作约定，不另建冲突流程。

### 5.1 分支

| 角色 | 分支 | 说明 |
|---|---|---|
| 集成分支 | `integration/v1.2` | 所有模块 PR 的目标分支 |
| A | `feature/account-center` | 账号与个人中心 |
| B | `feature/resource-module` | 资源与座位治理 |
| C | `feature/reservation-module` | 预约、续约、候补 |
| D | `feature/analytics-module` | 运营分析与导出 |
| 共享文件集成 | `chore/shared-integration` | B/负责人应用 SFCR 的短暂集成分支 |

### 5.2 PR 流程

1. 各成员从最新 `integration/v1.2` 创建/更新自己的 feature 分支。
2. 模块代码、模块测试、模块文档在 feature 分支完成。
3. PR 目标为 `integration/v1.2`，不得直接推 `main`。
4. 共享文件变更走 SFCR，由 B/项目负责人在 `chore/shared-integration` 应用，PR 合入 `integration/v1.2`。
5. 集成完成后，由项目负责人统一执行全系统回归，最后再走 `integration/v1.2 → main` 发布 PR。

### 5.3 SFCR 约定

现有共享文件修改申请机制：

- 文档目录：`docs/collaboration/`。
- 命名：`SFCR-<模块>-<序号>-<主题>.md`。
- 内容必须包含：申请目的、目标文件、插入锚点/完整 before-after、影响范围、依赖、验证方式、回退方式。
- A/C/D 不得直接修改共享注册表；A 的 app.py 路由注册、app.js 账号动作、D 的共享审计事件等都必须走 SFCR。
- B 正常为共享文件唯一修改人；B 超过 1 个工作日未处理时，由项目负责人授权备份处理人。
- SFCR 应用后必须登记 SHA、复核人和日期；模块成员在自己的测试中可以使用本地临时 router mount，但不得把临时注册提交为正式 `app.py`。

### 6.1 跨模块契约与测试夹具约定

以下契约由公共底座锁定，A/B/C/D 不得各自另立版本：

1. **M-04 资源停用释放预约**
   - B 在 `engine.py` 提供统一 helper：`release_affected_reservations(...)`。
   - 资源关闭/停用导致的预约统一置为 `cancelled`，`end_reason="resource_unavailable"`。
   - 该路径不记 `no_show`、不扣信用；C 只复用 helper/状态契约，不另写释放逻辑。
2. **M-03 强制改密**
   - 服务端统一返回 **HTTP 403**，错误码 **`PASSWORD_CHANGE_REQUIRED`**。
   - 白名单：`GET /api/auth/me`、`POST /api/auth/change-password`、`POST /api/auth/logout`。
   - 其他业务 API 在改密前一律拒绝。
3. **测试夹具**
   - 使用 `tests/conftest.py` 的 `ctx` 夹具时，必须使用 `tests/helpers.py` 的 `seed_fixture` ID：`S1~S5/T1/A1/Y1/R1/R2`。
   - 若测试使用文档中的 `S2023001/A9001/Y0001/A101`，必须显式初始化 `demo=True` 的独立测试库，不能与 `ctx` 夹具混用。
4. **审计接口**
   - 统一调用 `DomainEngine.audit_event(actor, action, target_type, target_id, *, result, details, before, after, now, ip)`。
   - `details/before/after` 中的 password/token/secret/credential/csrf/cookie 字段自动脱敏；B/C/D 不修改该签名。
5. **迁移版本预留**
   - 当前最新迁移版本：`2`。
   - 预留：`3 = 审计表/审计字段扩展`，`4 = B 模块资源/预约约束`；后续不得复用。

## 8. 验收标准

1. 代码修改范围符合本计划边界。

4. 原有测试不回归。
5. 共享文件变更已通过 SFCR 应用并登记。
