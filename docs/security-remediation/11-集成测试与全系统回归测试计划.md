# 集成测试与全系统回归测试计划

> 文档口径（v2.0.3，2026-11-26）：当前发布版本 **v2.0.3**；`pytest` **499 passed / 1 skipped**，Node **43 passed**；用户启动方式统一为安装 `setup.exe`。本文历史章节中的旧版本/测试数字仅代表当时基线，最新口径以根目录 `README.md` 与 `CHANGELOG.md` 为准。


## 1. 目的与范围

本计划用于验证 A/B/C/D 与共享层安全整改合并后的系统行为，重点不是重复各模块 25 条单元/API 测试，而是验证跨模块契约、状态联动、权限矩阵、事务/并发和完整业务链。

覆盖：

- 账号 → 资源 → 预约 → 签到 → 续约/违约/候补 → 分析 → 导出。
- 资源关闭/座位停用与预约状态。
- 账号停用/强制改密与各模块接口。
- 角色权限矩阵。
- 导出审计/CSV 安全/数据一致性。
- 并发预约、候补确认、凭证签发。
- 全量 pytest 回归。

## 2. 测试环境

- 代码：`integration/v1.2` 安全整改集成分支。
- 依赖：Python 3.12、pytest 8.3.4、httpx、FastAPI TestClient；前端 Node（如执行前端测试）。
- 数据库：独立临时 SQLite，不得使用生产/演示正式库。
- 时间：测试注入固定 `now`；跨日/时区测试单独准备。
- 服务：需要时使用 `127.0.0.1` 本地服务 + 测试库，不对外网开放。
- 浏览器：Playwright 如安装则执行前端 E2E；未安装则明确标记跳过，不伪造浏览器通过。

## 3. 测试数据准备

### 3.1 基础数据

- 房间：A101/B201，open；C301 closed（用于资源状态测试）。

  - pending（未来）。

## 5. 跨模块集成场景

### IT-01 账号与预约：账号停用后预约/签到/续约

- **参与模块：** A、C、共享层。
- **前置：** 学生有 pending/未来预约、已签发凭证、in_use 预约。
- **步骤：**
  1. sysadmin 通过 A 停用学生。
  2. 旧 session 调用 C 的预约/签到/续约。
  3. ACS 使用旧凭证签到。
  4. 重新登录。
- **预期：** 旧 session 401；普通/ACS 签到拒绝；续约拒绝；预约不被 in_use；无 no_show 误判；审计记录停用。
- **责任人：** A 主、C/共享层协作。

### IT-02 账号与预约：强制改密期间接口访问

- **参与模块：** A、C、共享层。
- **前置：** 新账号 `must_change_password=True`，已登录。
- **步骤：**
  1. 调 `/api/meta`、`/api/reservations`、`/api/me/dashboard`。
  2. 调 `/api/auth/me`、`/api/auth/change-password`、`/api/auth/logout`。
  3. 改密后重新登录。
- **预期：** 业务接口 403/409；允许接口正常；改密后恢复；旧 session 失效。
- **责任人：** A 主、共享层复核。

### IT-03 账号与权限：四角色矩阵

- **参与模块：** A/B/C/D/共享层。
- **前置：** 四角色登录；代表性接口。
- **步骤：** 按 00 计划权限矩阵逐项请求。
- **预期：** student 不能管理账号/资源/导出；teacher 只能教师看板/有限的个人接口；room_admin 可资源/分析/学生/黑名单/评价，不能参数/审计/导出；sysadmin 可参数/审计/导出/账号，不能黑名单/评价（按现有设计）；无垂直/水平越权。
- **责任人：** 负责人主、各模块复核。

### IT-04 资源与预约：关闭房间

- **参与模块：** B、C。
- **前置：** A101 有 pending/in_use/away 预约。
- **步骤：**
  1. room_admin 预览影响。
  2. 关闭 A101。
  3. 查询预约/slot/信用/通知。
  4. 运行 sweep 到开始后 16 分钟。
  5. 重复关闭。
- **预期：** 预约按 B/C 契约取消/释放；无 no_show/信用下降；通知/审计；重复关闭幂等。
- **责任人：** B 主、C 协作。

### IT-05 资源与预约：座位停用/维护/封禁

- **参与模块：** B、C。
- **前置：** 座位有 pending/in_use 预约；生效/未来封禁。
- **步骤：**
  1. 设置 disabled/maintenance。
  2. 创建当前封禁/未来封禁。
  3. 解封/到期。
  4. 查询预约/座位/信用。
- **预期：** 停用/维护按契约处理预约；封禁取消重叠预约；手工维护/disabled 不被解封误恢复；未来封禁不立即生效；不 no_show。
- **责任人：** B 主、C 协作。

### IT-06 资源恢复后预约

- **参与模块：** B、C。
- **前置：** 房间 reopened/座位 available/封禁释放。
- **步骤：** 学生创建预约/加入候补/确认。
- **预期：** 正常预约/候补；无旧状态残留；影响预览/统计正确。

### IT-07 预约与运营分析

## 6. 全系统业务链回归

### 6.1 正常链

1. sysadmin 创建/启用学生账号。
2. 学生首次登录/改密。
3. 查询房间/座位。
4. 创建预约。
5. 在窗口内签到。
6. 暂离/返座/签退或续约。
7. 评价/投诉（可选）。
8. D 分析更新。
9. sysadmin 导出 CSV，审计记录。
10. 账号/预约/资源状态一致。

**预期：** 所有接口 2xx/业务成功；状态/信用/统计/导出一致；无安全错误。

### 6.2 异常链

| 场景 | 预期 |
|---|---|
| 房间关闭 | 已有预约取消/释放，不 no_show，不扣信用 |
| 座位停用/维护 | 同上；解封不误恢复 |
| 账号停用 | 旧 session 401；普通/ACS 签到/续约拒绝 |
| 强制改密 | 业务 API 403，仅允许认证/改密/登出 |
| 黑名单/低信用 | 新预约/候补/签到/续约按规则拒绝 |
| 预约取消 | 状态/配额/通知正确 |
| no_show | 仅真实未签到/超时；资源关闭不误判 |
| 候补 | 资源/时间不合法时失效，不生成预约 |
| 事务失败 | 无部分数据 |
| 并发预约 | 只有一个成功 |

### 6.3 安全链

- 未登录访问所有受保护 API → 401。
- 学生/教师调用管理员接口 → 403。
- 跨用户预约/候补/投诉/评价 → 403。
- 缺失/错误 CSRF → 403。
- 导出非 sysadmin → 403。
- CSV 恶意字段 → 安全文本。
- 默认凭据/演示接口 → 不泄露正式管理员。
- 健康检查 → 不泄露内部细节。
- 日志/审计 → 无密码/token。

## 9. 并发场景

- 同座位同 slot 8 线程预约：1 成功。
