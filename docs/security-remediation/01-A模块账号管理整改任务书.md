### L-01 room_admin 账号列表权限过宽

#### 现状

- `GET /api/admin/users` 无路由级角色过滤；`engine.list_users` 允许 room_admin 和 sysadmin。
- room_admin 直接调用可获取所有角色账号，包括 sysadmin 的 ID、姓名、院系、状态、信用、`must_change_password`。
- 前端只给 sysadmin 显示账号页，但 API 未限制。

#### 具体修改要求

1. 明确 room_admin 的账号查询范围：默认只允许学生账号，且只返回管理学生所需字段。
2. sys_admin 保留全角色账号管理。
3. 对 `role=sys_admin`/`room_admin`/`teacher` 的查询，room_admin 应返回 403 或空集合；不要只靠前端隐藏。
4. 对 `/admin/students` 继续只返回学生；`/admin/users` 的权限策略需负责人确认。
5. 最小化返回字段：学生列表不需要 `must_change_password` 等敏感状态时移除。
6. 增加 API 测试，不能只测 engine。

#### 涉及文件/接口

- `SR/src/seat_reservation/domain/engine.py:2896-2909`
- `SR/src/seat_reservation/storage/repository.py:261-286`
- 前端：`app.js` 账号/学生页

#### 修改边界

- 若需要修改共享 `admin_routes.py`，A 只改账号相关段，先与 B/共享层确认。

#### 协作要求

### L-03 前端登录密码状态清理不充分

#### 现状

- `state.lastLoginPassword` 保存明文登录密码，并用于预填改密表单。
- `showLogin()` 不清空 `#password` 输入框；登出后隐藏登录区仍保留值。
- 密码不落盘，但共享工作站/扩展/未来 XSS 可读取。

#### 具体修改要求

1. 移除不必要的 `lastLoginPassword` 长期保留；改密表单不预填旧密码，或仅在用户明确操作时临时使用。
2. 在以下场景清空密码相关状态和 DOM：
   - 登录成功/失败后。
   - 登出后。
   - 切换账号/会话失效后。
   - 页面进入登录页时。
3. 不清空用户名以外的非敏感状态时，确保不残留上一个账号的导航/视图/数据。
4. 增加前端 Node 测试或手工验收步骤。

#### 涉及文件/接口

- `SR/src/seat_reservation/web/app.js:105,379,393,2967,2979,359-368`
- `SR/index.html:101`

#### 修改边界

- 只改 A 负责的登录/账户前端逻辑；不改认证后端。
- 不引入第三方前端框架或依赖。

#### 验收标准

- 登录失败/成功/登出后，`state.lastLoginPassword` 为空或不存在。
- 登出后 `#password.value` 为空。
- 改密流程仍可用，不要求用户重新输入明文旧密码也可以由用户主动输入。
- 不出现密码被写入 URL/localStorage/sessionStorage。
