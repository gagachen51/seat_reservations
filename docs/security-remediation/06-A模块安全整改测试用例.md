# A 模块安全整改测试用例

## 1. 测试范围

覆盖 A 模块账号生命周期、个人中心、强制改密、账号范围、前端密码清理，以及 A 与共享认证/C 预约的集成。

## 2. 测试环境及依赖

- 代码基线：`D:\seat_clean_baseline`（公共底座 + D 模块整改后），当前完整测试 **380 passed, 1 skipped**。
- 测试框架：pytest 8.3.4、FastAPI TestClient、httpx、临时 SQLite。
- 前端：Node.js（现有 `tests/account_frontend.test.cjs` 风格）。
- 运行目录：`SR`。
- 命令示例：

```bash
python -m pytest tests/test_account_engine.py tests/test_account_api.py tests/test_api.py -q
node --test tests/account_frontend.test.cjs
```

- `app.py` 的 `account_routes` 注册、`app.js` 四个账号动作、`deps.py` 强制改密门禁均已就绪；`A-SEC-023/024` 可直接运行真实 `create_app()`，不需要临时 mount Router 或等待共享层 SFCR。
- 若 A-SEC-025 依赖的 C `M-06` 尚未合入，可先标记 `pytest.mark.xfail`/`xfail`，联调阶段转为强制通过；不得伪造通过。

## 3. 测试数据准备

- 使用临时数据库；若使用 `conftest.py` 的 `ctx` 夹具，必须使用 `tests/helpers.py` 的 `seed_fixture` ID：`S1~S5/T1/A1/Y1/R1/R2`。
- 若沿用本文示例的 `S2023001/A9001/Y0001/A101`，必须显式初始化 `demo=True` 的独立测试库；不得与 `ctx` 夹具混用。
- 额外账号 `TMP-STU`、`TMP-ADMIN` 由测试夹具创建。
- 需要预约时使用 C 的临时夹具/引擎创建，不连接生产数据。

## 5. 详细测试样例

### A-SEC-001 账号创建参数校验

- **测试类型：** 单元
- **对应审计问题：** H-02
- **测试目的：** 验证账号 ID/姓名/角色/密码的 engine 级校验，避免非法账号落库。
- **前置条件：** 临时 DB；sysadmin Actor。
- **测试步骤：**
  1. 调用 `DomainEngine.create_user`，分别传入空白 ID、含 `/` 或 `\` 的 ID、超过 64 字符 ID、空姓名、非法角色、7 位密码。
  2. 每次调用后查询 users 表。
- **输入数据：** `user_id=""`、`"A/B"`、`"A\\B"`、`"x"*65`；`role="super_admin"`；`password="1234567"`。
- **预期结果：** 每次抛 `ValidationFailed`/`Conflict`；users 表无新增行；错误信息不含内部 SQL。
- **测试方式：** pytest 单元测试。
- **优先级：** P0

### A-SEC-002 最后管理员与自停用保护

- **测试类型：** 单元
- **对应审计问题：** H-02
- **测试目的：** 验证 sysadmin 降级/停用的最后管理员保护。
- **前置条件：** 仅一个 active sysadmin；临时 DB。
- **测试步骤：**
  1. 对唯一 sysadmin 调用 `set_user_role(..., "student")`。
  2. 对自身调用 `set_user_status(..., "disabled")`。
  3. 创建第二个 active sysadmin 后重复降级/停用。
- **输入数据：** `user_id=Y0001`、`role=student`、`status=disabled`。
- **预期结果：** 前两步抛 `RuleViolation`（PR-14）；有第二个管理员后操作成功；审计记录 before/after。
- **测试方式：** pytest 单元测试。
- **优先级：** P0

### A-SEC-003 重置密码生成一次性密码并撤销会话

- **测试类型：** 单元
- **对应审计问题：** H-02 / M-03
- **测试目的：** 验证重置密码设置 `must_change_password=True`、删除所有会话、返回随机初始密码。
- **前置条件：** 目标用户有 2 个 session。
- **测试步骤：**
  1. 创建 session。
  2. 调用 `engine.reset_user_password`。
  3. 检查 users/sessions 表和返回数据。
- **输入数据：** `user_id=S2023001`。
- **预期结果：** 返回 `initial_password` 长度足够且不等于旧密码；`must_change_password=True`；sessions 0；审计不含密码/hash。
- **测试方式：** pytest 单元测试。
- **优先级：** P1

### A-SEC-004 强制改密依赖的单元行为

- **测试类型：** 单元
- **对应审计问题：** M-03
- **测试目的：** 验证新增的服务端强制改密判断只允许白名单接口。
- **前置条件：** 构造 `AuthSession(user.must_change_password=True)`。
- **测试步骤：**
  1. 调用强制改密依赖/辅助函数，传入不同 path。
  2. 检查允许/拒绝集合。
- **输入数据：** `/api/auth/me`、`/api/auth/change-password`、`/api/auth/logout`、`/api/meta`、`/api/reservations`。
- **预期结果：** 前 3 个允许；后 2 个抛 `Forbidden`/返回 403，错误码 `PASSWORD_CHANGE_REQUIRED`。
- **测试方式：** pytest 单元测试。
- **优先级：** P1
