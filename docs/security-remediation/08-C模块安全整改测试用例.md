# C 模块安全整改测试用例

> 文档口径（v2.0.3，2026-11-26）：当前发布版本 **v2.0.3**；`pytest` **499 passed / 1 skipped**，Node **43 passed**；用户启动方式统一为安装 `setup.exe`。本文历史章节中的旧版本/测试数字仅代表当时基线，最新口径以根目录 `README.md` 与 `CHANGELOG.md` 为准。


## 1. 测试范围

覆盖预约创建、签到/签退、暂离/返座、续约、候补、状态转换、资源变更联动、账号限制、ACS、事务与并发。

## 2. 测试环境及依赖

- 代码基线：`D:\seat_clean_baseline`（公共底座 + D 模块整改后），当前完整测试 **380 passed, 1 skipped**。
- pytest 8.3.4、FastAPI TestClient、临时 SQLite、线程测试。
- 运行目录：`SR`。
- 命令示例：

```bash
python -m pytest tests/test_extension.py tests/test_waitlist_cancel.py tests/test_safety_fixes.py tests/test_concurrency.py -q
```

- M-04 使用 B 的 `release_affected_reservations` helper 和临时预约夹具，不依赖 B 分支已合并；最终跨模块验证见文档 11。
- **M-04 统一断言：** 预约 `cancelled`、`end_reason="resource_unavailable"`、不 `no_show`、不扣信用。

## 3. 测试数据准备

- 临时 DB；若使用 `ctx` 夹具，必须使用 `helpers.seed_fixture` 的 `S1~S5/T1/A1/Y1/R1/R2`。
- 若使用本文示例的 `A101/A9001/Y0001/S2023001`，必须显式初始化 `demo=True` 的独立测试库，不得与 `ctx` 夹具混用。
- 房间 A101 open/closed；座位 A101-001 available/disabled/maintenance；封禁生效/未来。
- 预约：pending/in_use/away/completed/cancelled/no_show/released。
- 候补：queued/notified/confirmed/expired/cancelled。
- 时间：使用注入 `now`，固定日期/时段，避免系统时钟波动。
- 不连接生产数据。

## 5. 详细测试样例

### C-SEC-001 续约规则单元

- **测试类型：** 单元
- **对应审计问题：** M-06 / L-07（基线）
- **测试目的：** 验证续约状态、时间、粒度、上限、冲突规则。
- **前置条件：** `reservation_rules` 纯函数。
- **测试步骤：**
  1. 对 pending/in_use/away/completed 调用 `extension_state_error`。
  2. 测试 1/30/1440 分钟，超过 `booking.max_minutes`/daily 额度。
  3. 测试边界/冲突。
- **输入数据：** 状态、`now`、`end_at`、`extra_minutes`。
- **预期结果：** `in_use/away` 且未结束允许；pending/completed 拒绝；非 30 分钟粒度拒绝；超上限/quota/冲突拒绝；错误规则正确。
- **测试方式：** pytest 单元。
- **优先级：** P1

### C-SEC-002 候补校验纯函数单元

- **测试类型：** 单元
- **对应审计问题：** M-07
- **测试目的：** 验证候补状态、开放时间、座位/房间/封禁判定辅助函数。
- **前置条件：** 新增/调整的纯规则函数。
- **测试步骤：**
  1. 对 queued/notified/cancelled 状态测试取消/确认。
  2. 测试开放时间内/外、座位可用/停用/维护、封禁重叠。
- **输入数据：** `WaitlistEntry`、room/seat/block 状态。
- **预期结果：** 只有合法 queued/notified 可操作；开放时间外/停用/封禁返回明确错误；正常候选通过。
- **测试方式：** pytest 单元。
- **优先级：** P2

### C-SEC-004 凭证签发幂等/并发单元

- **测试类型：** 单元

### C-SEC-005 sweep 分类单元

- **测试类型：** 单元
- **对应审计问题：** M-04 / M-06

- **测试步骤：**
  1. 运行 `run_timeout_sweep(now)`。
  2. 检查每类预约状态/违规/信用。
- **输入数据：** 预约列表；`now`。
- **预期结果：** 资源关闭预约不 no_show；正常未签到 no_show；away 超时 released + 违规；超时签退按规则；重复 sweep 不重复。
- **测试方式：** pytest 单元。
- **优先级：** P1
