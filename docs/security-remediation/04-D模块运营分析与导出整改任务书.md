## 3. 问题逐项说明

### L-04 CSV 公式注入防护边缘字符

> **状态：已完成并验证。** 7 类导出统一使用 `_csv_safe`，D 专项测试已覆盖。

#### 现状（审计时）

`SR/src/seat_reservation/api/routes/admin_routes.py:536-541`：

```python
def _csv_safe(value):
    if isinstance(value, str) and value.startswith(("=", "+", "-", "@", "\t", "\r")):
        return "'" + value
    return value
```

已覆盖 `= + - @ \t \r`；未覆盖 `\n`、NUL、BOM、部分 Unicode 空白。大部分用户字段在 engine 中被 `.strip()`，但 NUL/BOM 不会被去除。现有测试只覆盖 `=`。

#### 具体修改要求

1. 明确 CSV 清洗策略（建议保持“前缀单引号”风格）：
   - 对字符串先规范化/移除控制字符（NUL、BOM、CR/LF 等）。
   - 若清理后以 `= + - @ \t \r \n` 开头，加 `'`。
   - 对合法中文、数字、日期、普通文本保持不变。
2. 评估是否对 `kind`/表头也做静态校验；表头当前固定，不应被用户输入污染。
3. 处理 Excel/LibreOffice 对前导空白、NUL、BOM 的差异；不要只依赖 `startswith` 原始字符串。
4. 增加边缘字符测试：`=`, `+`, `-`, `@`, `\t`, `\r`, `\n`, `\x00`, `\ufeff`, 组合、正常中文/数字/日期。
5. 不改变 CSV UTF-8 BOM、`Content-Disposition`、列顺序和已有正常数据格式。

#### 涉及文件/接口

- `SR/src/seat_reservation/api/routes/admin_routes.py:536-541,543-564`
- `SR/src/seat_reservation/storage/export_queries.py`
- `SR/src/seat_reservation/storage/repository.py:2070-2143`
- 测试：`tests/test_analytics_api.py`

#### 修改边界

- 只改导出清洗/测试，不改业务指标。
- 如果清洗策略变化影响已有测试，需同步调整测试预期并说明。
- 不修改前端下载链接格式。

#### 验收标准

- 所有危险前缀在 CSV 单元格中被安全处理，不触发公式。
- 正常中文/数字/日期/空值保持原样。
- 七类导出均使用同一清洗函数。
- 边缘字符测试覆盖并通过。

### L-06 导出审计

> **状态：已完成并验证。** 成功/拒绝导出均写 `audit_event`，不记录 CSV 全文或凭据。

#### 现状（审计时）

- `engine.export_rows` 只做权限/日期校验，不写审计。
- `admin_routes.export_csv` 只返回 CSV，无审计事件。
- HTTP 访问日志有路径，但不是不可变审计，且不含导出类型/过滤条件/行数。

#### 具体修改要求

1. 在导出成功（或尝试）时写入审计：
   - 操作者 ID/角色。
   - 导出类型 `kind`。
   - 时间。
   - 日期过滤 `date_from/date_to`（如有）。
   - 行数、是否被限制/拒绝。
2. 审计内容不得包含：
   - 密码、session token、CSRF token。
   - 导出的完整敏感内容（不要复制 CSV 数据）。
3. 复用共享层统一审计格式；D 不自行定义不兼容表结构。
4. 建议对拒绝的导出（403/400）也记录安全事件，至少记录操作者和 kind；不要记录完整请求体。
5. 与共享层 L-06 协作：共享层定义 `audit` 事件规范，D 接入导出事件。

#### 涉及文件/接口

- `SR/src/seat_reservation/domain/engine.py:3068-3082`
- `SR/src/seat_reservation/api/routes/admin_routes.py:543-564`
- 共享审计：`SR/src/seat_reservation/domain/engine.py:_audit` 或共享审计服务
- 测试：`tests/test_analytics_api.py`、`tests/test_admin.py`

#### 修改边界

- D 负责导出事件；共享层负责审计表/格式/轮转。
- 不改变导出权限（sysadmin only）。
- 不把导出数据全文写入审计。

#### 验收标准

- 每次成功导出有审计记录，包含 actor/kind/时间/过滤条件/行数。
- 拒绝导出有明确安全记录（至少 actor/kind/结果）。
- 审计不含敏感数据。
- 现有导出权限/格式测试不回归。

### L-09 极端日期输入 500

> **状态：已完成并验证。** `OverflowError`/`ValueError` 已转为 422。

#### 现状（审计时）

`_resolve_analytics_dates` 对单边日期做 `± timedelta(days=6)`；`date_to=0001-01-01` 或 `date_from=9999-12-31` 会抛 `OverflowError`，被通用异常处理为 500。

#### 具体修改要求

1. 在日期窗口计算前做边界检查：
   - `date_from`/`date_to` 必须在合理数据库/业务范围。
   - 单边窗口计算使用安全函数，捕获 `OverflowError`/`ValueError`。
2. 非法/溢出返回 422/400，错误信息明确但不泄露内部堆栈。
3. 保持现有规则：
   - 双边缺失 = 7 天。
   - 单边缺失 = 对称 7 天。
   - 最大 90 天。
   - `from > to` 拒绝。
4. 增加测试：最小/最大日期、闰年、单边极端、91 天、倒置、非法格式。
5. 不改变正常分析结果。

#### 涉及文件/接口

- `SR/src/seat_reservation/domain/engine.py:3012-3042`
- `SR/src/seat_reservation/api/routes/admin_routes.py:54-71`
- 测试：`tests/test_analytics_engine.py`、`tests/test_analytics_api.py`

#### 修改边界

- 只改日期解析/校验，不改统计 SQL。
- 错误码使用现有 `ValidationFailed` 或统一 422。

#### 验收标准

- 极端日期返回 422/400，不是 500。
- 正常 7/30/90 天、单边窗口、闰年结果不变。
- 分析接口错误不泄露堆栈/SQL。

### L-10 导出与通知资源限制

> **状态：已完成并验证。** 导出 366 天/10000 行上限；通知 100 条由共享层完成。

#### 现状（审计时）

- 4 类导出（complaints/blacklist/credit_logs/waitlist）无 `LIMIT`，无最大日期跨度；CSV 全量内存构造。
- 3 类（reservations/violations/audit）固定 `page_size=10000`，超出静默截断。
- `POST /api/notifications/read` 的 `ids` 无长度上限，SQL 占位符随输入增长。
- 无应用级请求体大小限制。

#### 具体修改要求

1. 导出：
   - 已锁定最大日期跨度 **366 天**（`MAX_EXPORT_DAYS`）；不得改变分析 90 天规则，导出规则单独定义。
   - 已锁定最大行数 **10,000 行**（`MAX_EXPORT_ROWS`）；超限返回 422，不静默截断。
   - 7 类导出统一行为；查询多取 1 行用于超限探测。
2. 通知：
   - `ids` 已由共享层锁定 `max_length=100`；超限 422。
   - 超限 422，不执行 SQL。
3. 请求体大小：
   - 由共享层/部署层增加限制；D 在通知/导出接口做输入上限。
4. 增加大体量/超限测试，不断言真实生产数据量。

#### 涉及文件/接口

- `SR/src/seat_reservation/domain/engine.py:3068-3082`
- `SR/src/seat_reservation/storage/repository.py:2070-2143`
- `SR/src/seat_reservation/storage/export_queries.py`
- `SR/src/seat_reservation/api/routes/common_routes.py:28-29,96-103`（通知；共享层协作）
- `SR/src/seat_reservation/api/routes/admin_routes.py:543-564`
- 测试：`tests/test_analytics_api.py`、`tests/test_api.py`

#### 修改边界

- D 主责导出限制；通知 ID 限制需要共享层修改 `common_routes.py`，通过 SFCR。
- 不改变分析接口 90 天规则；导出另定上限需负责人确认。
- 不删除数据、不改变导出列。

#### 验收标准

- 导出超日期跨度/行数返回明确 4xx，不静默截断。
- 7 类导出一致。
- 通知 ID 超限 422，不执行 SQL/不产生 503。
- 正常导出/通知不受影响。
